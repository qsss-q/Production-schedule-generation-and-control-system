# 07. Технический стек: решение и обоснование

**Статус:** принято командой, требует письменного подтверждения заказчика
**Дата:** 2026-10-18

Документ фиксирует отклонение от рекомендованного методичкой стека. Методичка
требует в итоговой презентации «описание ограничений и возможных направлений
развития», поэтому отклонение должно быть аргументировано, а не подразумеваться.

---

## 1. Решение

Проект пишется на **Java 21 LTS + Spring Boot 3.4**.

Методичка рекомендует C# / .NET 8 (ASP.NET Core, Blazor, EF Core, Hangfire,
xUnit). Это **рекомендация, а не требование**: в формулировке методички
раздел назван «Рекомендуемый стек технологий», а перечень требований к результату
стек не включает.

## 4. Соответствие стеков

| Рекомендовано методичкой | Выбрано | Комментарий |
|---|---|---|
| C# 8+ | **Java 21 LTS** | LTS, виртуальные потоки |
| .NET 8+ | **Spring Boot 3.4** | Требует Java 17+, берём 21 |
| ASP.NET Core Web API | **Spring Web MVC** | Контракт REST не меняется |
| Blazor Server / WASM | **React или Vue** | Фронт отдельной командой, стек не зафиксирован |
| EF Core | **Spring Data JPA (Hibernate 6)** | Миграции — Flyway |
| PostgreSQL / MS SQL | **PostgreSQL 16** | Рекомендация методички, без изменений |
| Hangfire / Quartz.NET | **Quartz Scheduler 2.3** | Импорт файлов, пересчёт расписаний |
| Docker | **Docker + docker-compose** | Без изменений |
| xUnit | **JUnit 5 + AssertJ** | + Testcontainers для БД |
| Swagger / OpenAPI | **springdoc-openapi 2.x** | `/v3/api-docs`, `/swagger-ui.html` |
| SignalR (для REALTIME) | **WebSocket + STOMP** | Топики вместо групп |

### Что добавляем сверх методички

| Компонент | Зачем |
|---|---|
| **Flyway** | Миграции БД версионируются в git. `ddl-auto` в приложении — **выключить** |
| **Testcontainers** | Интеграционные тесты на настоящем PostgreSQL, а не H2 |
| **virtual threads** | Планировщик считает расписание для 69 печей — блокирующие задачи дешёво параллелить |
| **MapStruct** | Маппинг JPA-сущностей в DTO без ручного копирования |
| **records** | DTO как `record` — иммутабельность бесплатно |

## 5. Структура проекта

```
koks-scheduler/
├── pom.xml
├── docker-compose.yml          # postgres + приложение
├── src/main/java/ru/evraz/koks/
│   ├── KoksApplication.java
│   ├── config/                 # WebSocket, OpenAPI, Quartz, Jackson
│   ├── domain/                 # JPA-сущности и enum'ы
│   │   ├── entity/
│   │   └── enums/              # OperationStatus, Severity, MachineType...
│   ├── repository/             # Spring Data JPA
│   ├── service/
│   │   ├── planner/            # ★ ядро: серийность, цикличный график, метрики
│   │   ├── simulator/          # генерация телеметрии и отказов
│   │   └── import/             # разбор CSV/JSON, отчёт об ошибках
│   ├── web/
│   │   ├── controller/
│   │   ├── dto/                # record-ы запросов и ответов
│   │   └── error/              # @RestControllerAdvice, коды ошибок
│   ├── jobs/                   # Quartz Job-ы
│   └── messaging/              # STOMP, рассылка событий
├── src/main/resources/
│   ├── application.yml
│   └── db/migration/           # V1__init.sql, V2__seed_reference_data.sql
└── src/test/
```

**Ключевое требование:** пакет `service.planner` не должен зависеть от Spring.
Планировщик — чистые функции над доменными объектами, чтобы его можно было
гонять в тестах и из симулятора без контекста. Это же то, что просил
Игорь: «нарисовать можно ещё много всего, но если бэка под этими ручками
не будет — получится не круто».

## 6. Если заказчик настаивает на C#/.NET

Тогда предметная часть (`00`–`06`) **не меняется вообще** — она не привязана
к стеку. Меняется только реализация:

| Что переделать | Трудоёмкость |
|---|---|
| Контроллеры | Переписать по [03-контракт-api.md](03-контракт-api.md), контракт тот же |
| JPA-слои | EF Core |
| Quartz Job-ы | Hangfire |
| STOMP-рассылка | SignalR |
| Тесты | xUnit |

Оценка: 2–3 дня работы планировщика и справочников — то есть именно той части,
где риск не в языке, а в предметной области. **Поэтому и важно подтвердить
до начала кодирования, а не после.**

## 7. Соглашения по коду

| Правило | Решение |
|---|---|
| Логирование | SLF4J + Logback, структурные поля через MDC (`requestId`, `ovenNumber`) |
| Валидация | `jakarta.validation` (`@NotNull`, `@Positive`) + доменная проверка в планировщике |
| Транзакции | `@Transactional` на сервисах; планировщик — `@Transactional(propagation = REQUIRES_NEW)` |
| Ошибки | Единый `@RestControllerAdvice`, формат конверта из [03](03-контракт-api.md) |
| Время | `java.time.*` обязательно. `Instant` для хранения, `LocalDateTime` только для смен |
| Идентификаторы | `UUID`, генерируемые приложением |
| JSON | Jackson, `snake_case` через `@JsonNamingStrategy`, чтобы совпадало с контрактом |
| Тесты | JUnit 5, `@SpringBootTest` + Testcontainers, юнит-тесты планировщика — без Spring |
