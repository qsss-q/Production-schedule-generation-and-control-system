# koks-simulator (v0.1)

Чистое in-memory ядро симуляции коксовой батареи. Без веб-слоя, без БД,
без фреймворков — как было зафиксировано в `docs/07`: движок и планировщик
не должны зависеть от Spring.

## Запуск

```bash
./gradlew run      # демо: 3 суток, батарея 69 печей, схема 9-2
./gradlew test     # 31 тест: серийность, слоты, машины, отказы, API движка
```

Java 21 (toolchain подберёт JDK). Wrapper — Gradle 8.14.2.

## Что умеет v0.1

**Серийность S–K** (`Seriality`) — построение порядка выдачи по документации
`docs/05` §2. Печь `n` принадлежит серии `((n−1) mod S)+1`, выдача идёт
сериями 1…S подряд.

**Машины комплекта** — отдельные объекты `Machine` с паспортом
`MachineKind`: коксовыталкиватель (КВ), двересъёмная машина (ДСМ),
тушильный вагон (ТВ), углезагрузочный вагон (УВ). У каждой машины:

- позиция вдоль батареи (номер печи; башни — за торцом);
- кинематика: маршевая скорость, ускорение, приладка у печи;
- занятость `freeAt`, счётчик задач и накопленная рабочая загрузка;
- время переезда по трапецеидальному профилю:
  `L ≥ v²/a → t = L/v + v/a`, иначе `t = 2·√(L/a)`.

Симулятор спрашивает `readyAt(...)`, а затем фиксирует задачу `commit(...)`.
Срез состояния — `Simulator#machines()` (живые объекты) и
`Simulator#machineStatus()` (для графика/карты машин).

**Выдача печи** — Δt = T_цикл / N. Начало выталкивания = max(слот,
готовность печи, готовность КВ, ТВ и ДСМ). Цепочка работ:

1. ДСМ снимает дверь;
2. КВ выталкивает пирог, ТВ принимает его у печи;
3. ТВ везёт кокс к тушильной башне и разгружается;
4. УВ берёт шихту у угольной башни и загружает камеру;
5. ДСМ ставит дверь; коксование начинается с конца загрузки.

**Передержка** — ожидание выдачи дольше `toleranceMin` (5 мин) даёт событие
`OVERHOLD`; опоздание к слоту — `LATE`. Семантика соответствует `docs/02`:
жёлтый = срыв графика.

**Отказы** — два типа: отказ выталкивания при выдаче (затягивает поток на
время ремонта) и отказ обогрева камеры (печь в `FAULT`, коксование
сдвигается). Вероятности в `SimConfig`, между отказами — экспоненциальный
закон.

**Детерминизм** — одна конфигурация и один `seed` дают одинаковую event-ленту;
`advance()` можно вызывать частями.

## API для Spring-бэкенда

Модуль собирается как `java-library` с координатами
`ru.evraz.koks:koks-simulator`, поэтому Spring-приложение подключает его как
зависимость, а фреймворки остаются снаружи модели.

| Метод | Назначение |
|---|---|
| `config()`, `ovenCount()`, `deltaMin()`, `order()`, `nextIssue()` | метаданные батареи и плана |
| `state(n)`, `readyAt(n)`, `loadDoneAt(n)`, `dischargeAt(n)` | снимок печи для карточек и мнемосхемы |
| `machineStatus()`, `machines()` | машины: позиция, занятость, `runningAt(t)` |
| `forecast(limit)` | ближайшие выдачи: печь, слот, готовность, прогноз начала |
| `events()` | прошедшие события для журнала |
| `injectFailure(PUSH_JAM / OVEN_HEATING)` | кнопка «Сгенерировать отказ» |
| `advance(min)` | шаг модельного времени |

`forecast` возвращает не больше одной выдачи на печь (≤ N): для следующих
оборотов нужен отдельный прогноз. `Simulator` не потокобезопасен —
`advance()` и чтение снимков должен сериализовать внешний слой.

Подключение через composite build:

```kotlin
// backend/settings.gradle.kts
includeBuild("../simulator")

// backend/build.gradle.kts
implementation("ru.evraz.koks:koks-simulator")
```

## Модель в цифрах (по умолчанию)

| Параметр | Значение | Комментарий |
|---|---|---|
| Печей | 69 | батареи ЕКС |
| Серийность | 9-2 | выбирается оператором |
| T_цикл | 840 мин | оборот |
| T_кокс | 830 мин | готовность за ~3 мин до слота — без передержки в номинале |
| Δt выдачи | 840/69 = 12.17 мин | |
| Шаг осей камер | 1.26 м | КБ-5; КБ-7 — 1.40 м |
| Выталкивание | 2 мин | КВ |
| Снятие / установка двери | 1 / 1 мин | ДСМ |
| Загрузка камеры | 5 мин | УВ |
| Приём пирога / разгрузка | 1 / 2 мин | ТВ |
| Башня от торца батареи | 40 м | тушильная и угольная |
| Допуск передержки | 5 мин | при превышении — severity yellow |
| Отказ выталкивания | p = 0.004 на выдачу | ~1–2 раза за оборот |
| Отказ обогрева | λ = 0.0008 1/ч на печь | ~2–3 раза в сутки на батарею |

Нормативы `docs/06` в модели: выдача → загрузка = 2 + 5 = 7 мин ≤ 8;
от снятия двери до установки в стационаре ≈ 9.5 мин ≤ 10.

| Машина | Код | Маршевая скорость | Приладка |
|---|---|---|---|
| Коксовыталкиватель | КВ | 102 м/мин (1.7 м/с) | 1.0 мин |
| Двересъёмная машина | ДСМ | 90 м/мин (1.5 м/с) | 0.5 мин |
| Тушильный вагон | ТВ | 90 м/мин (1.5 м/с) | 0.5 мин |
| Углезагрузочный вагон | УВ | 150 м/мин (2.5 м/с) | 0.5 мин |

Скорости — паспортные/оценочные ТТХ, в документации проекта не нормированы:
одна точка правды — `MachineKind`, помечено «уточнить по паспортам ЕКС».
Приём кокса идёт со скоростью штанги 0.5 м/с и учтён в длительности
выталкивания.

## Что осознанно не вошло в v0.1

- тепловой расчёт периода коксования (T_кокс — входной параметр);
- телеметрия (температурный профиль камер);
- HTTP/STOMP-интерфейс — появится в бэкенде по контракту `docs/03`;
- алгоритмы планирования b1/b2/b3 и проверки ограничений H1…H9;
- несколько батарей и несколько комплектов машин;
- ремонты/перестановки машин, кроме отказа выталкивания.
